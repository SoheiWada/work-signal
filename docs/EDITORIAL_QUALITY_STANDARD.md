# WORK SIGNAL — Editorial Quality & Data Language
改訂: 2026-11-03 / 新規制作から適用

## 1. DEEP DIVEは字数ではなく「分析の独自価値」で判断する
サイト内の `reading_format()` は章数・字数による**表示上の一次判定**。その結果がDEEP DIVEであっても、原稿を深い分析だと自動保証するものではない。編集の最終判定は以下の4点すべてを確認する。

1. **SOURCE** — 一次資料の公表日時、対象範囲、数値、原文との一致を照合し、確認した事実と推論を区別する。
2. **CONTEXT** — なぜいま起きたかを、過去・制度・他社・市場・技術仕様など妥当な比較軸で説明する。
3. **IMPLICATION** — 仕事・経営・利用者の判断にどう響くかを具体的に述べる。「重要だ」「注目だ」だけで終わらない。
4. **LIMITATION** — まだ分からないこと、適用対象、調査母数、観測上の限界、反対解釈の余地を明記する。

4点のうちいずれかが欠ける原稿は、**BRIEFで簡潔に届ける**か、資料を足してからDEEP DIVEとして出す。形式の数だけを理由に引き延ばしてはならない。速報として価値のあるBRIEFを下位扱いしない。

## 2. 制作・校正ゲート
- リード＝確認されたニュースの核心。 `quick_take`＝重要な理由・仕事への意味・留保。重複させない。
- 数字は数字・単位・対象期間・母数・設問・根拠URLを同時に検証する。何らかの数値比較をする場合、母数や定義の不一致を隠さない。
- 見出し・本文・出典図版に現れる主要数値を突き合わせ、単位抜けや見出しの数字欠落を防ぐ。
- 想定・計画・実績・実証結果を同義として記述しない。製品や調査の提供元の利害も必要に応じて明示する。
- `reading_format_override` は20字以上の理由を保存し、技術的な長さ判定を例外的に上書きするためのもの。無根拠なDEEP DIVE指定をしない。
- 公開前にSEO/記事URL/SECURITY WATCH/出力テストを通す。既存のSNS投稿承認・台帳は変更しない。

## 3. 既存記事は選抜改稿
一括改稿はしない。既存記事は次の順でレビューする。

- **A / 最優先**：重大な数値・見出し誤記、一次資料との不整合、対象条件が誤解される記事。確認した事実のみ修正し更新日を適切に記録。
- **B / 高**：Search Consoleの表示が多いのにCTRが低い、読了後の回遊が弱い、競合より深い解釈を提供できる既存記事。
- **C / 通常**：陳腐化した記事の年次点検。時点を維持したアーカイブとして価値があれば改稿不要。

候補例：JP Incident Monitorの検索需要がある場合はクリック率と検索意図を分析。マネジメント調査記事は数値の誤記を優先訂正。通常の脆弱性速報は後から長文化せず、修正版・悪用確認など重大な新事実がある場合に追記する。

## 4. DATA FREQUENCY — 独自ビジュアル言語
**同じブランド要素を再現可能なテンプレート**として使う。

- 背景：`#F2EFE7`（紙）、文字：`#191918`（墨）、数値強調：`#FA4C24`。角丸カード・影・装飾アイコンは原則使わず、罫線・余白・数字・シグナル線で構成する。
- **Metric Pair**：別々の設問の数値を左右で見せる。バーは個別の0–100%基準。異なる母数を共通分母であるかのように見せない。
- **Process Comparison（今後の型）**：同一条件でのプロセスや選択肢を比較。前提条件と比較できない要素を脚注に記す。
- **Signal Timeline（今後の型）**：発表→施行→実績などを時点ごとに示す。未確定日付は点線・保留で表現する。
- 図ごとに元の数値・単位・母数・調査手法・一次情報へのリンク・限界を必須とする。正確な分母のない%差や因果効果を図示しない。
- 現在の実装：`data/editorial-figures.json` の編集承認済み定義に基づき `scripts/build_site.py:editorial_evidence_figure()` がMetric Pairを静的HTML化する。原稿に存在しない数値、範囲外の%、不正な母数はビルドで拒否する。JSなしでも読める。

## 5. ブランド・品質保証
既存記事のURL、title/description、canonical、JSON-LD、OGP、公開日を原則保持。表示の最終検収はPC・390px・320px、長い日本語見出し、SECTION / SECURITY WATCHと独立した表示、スクリーンリーダー用ラベルを確認する。見た目の強さだけでなく、**データの正しさと読みやすさ**を評価する。
