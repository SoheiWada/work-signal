# 読了後の導線とThreads改善の段階導入

作成：2026-11-05 JST。MUSEの提案をもとに、サイト導線→固定投稿→冒頭比較の順で導入する。

## 1. 記事末尾：今回の実装

- 「この先の変化も、追うなら。」を共有ボタンの前に配置。公式Threads / Instagram、RSS、編集方針へのリンクを設ける。
- 案内文：**AI・仕事・経済の変化を、一次情報から。次の判断材料を、公式SNSでも。**
- 共有は「誰かの判断材料に、なりそうなら。」として独立。共有先・コピー・SECURITY WATCHへ戻る導線・ALL SIGNALSを維持する。
- CSS・共有JavaScriptの参照に更新番号を付け、旧キャッシュと新HTMLの組み合わせによる崩れを防ぐ。
- 静的記事と動的記事を揃える。非公開プレビューには共有・フォロー導線を表示しない。
- GA4が利用可能な場合のみ `social_follow_click` を送る。パラメーターは `platform`（threads / instagram / rss）、`article_id`、`placement=article_end`、`link_url`。個人情報や認証情報は含めない。計測失敗でも通常のリンク遷移を妨げない。
- このイベントは**公式プロフィール／RSSへのリンククリック**。実際のフォロー完了、閲覧完了、個人単位の転換を意味しない。RSSも別集計し、SNSの数に混ぜない。
- GA4のカスタムディメンション登録・レポート取得・キーイベント指定は今回行わない。集計を読む場合は取得可否を確認し、取得不可を0に置き換えない。標準の外部リンクclickイベントと合算しない。
- 記事本文、公開承認フラグ、SNS台帳、Instagramフィードの保護停止、投稿頻度は変更しない。

## 2. Threadsの自己紹介：固定用原稿（未投稿・未固定）

プロフィールを訪れた人に媒体・読者価値・編集基準を伝える。過去記事は当時の記事として紹介する。投稿直前に代表記事の公開状態と一次情報を再確認する。

```text
WORK SIGNALです。
AI・仕事・経済のニュースを、一次情報から読み解いて届けています。

フォローすると、こういう変化が追えます。
・公式発表や文書から確認した事実と、編集部の解釈を分けて解説。数字には時点を添えます
・仕事に関わるAIの動きと、マネジメントの判断材料
・実務に直結する脆弱性情報（SECURITY WATCH）

これまでの記事から2本。
Nettyの脆弱性を読む（SECURITY WATCH）：
https://signal.amberlight.co.jp/articles/20261027-netty-tcnative-tls-cve-2026-116539-116540-116541/
富士通のCopilot展開を読む（AI×マネジメント）：
https://signal.amberlight.co.jp/articles/20261028-fujitsu-copilot-100k-service-desk-ai/

運営：アンバーライト合同会社。
編集方針：https://signal.amberlight.co.jp/about/
```

アプリの文字数・リンク仕様に合わせ、本文に収まらない場合は代表記事を返信に分ける。自動キューに架空の記事を追加して投稿しない。固定した実投稿URLと実施時点は完了後に記録する。現時点では原稿準備のみ。

## 3. 冒頭2行の比較：実施条件（未開始）

現在の投稿処理は記事タイトルから始まる。したがって「ラベル＋見出し」を現状の対照群としない。既存の手動指定 `social_threads_text` もあるため、対象ごとに現状の実際の文面を先に保存する。

| 条件 | 対照A | 試案B |
| --- | --- | --- |
| 冒頭2行 | 対象記事で現在生成されるタイトル・導入 | 一次情報で確認した主体・数値＋仕事への意味や未確定点 |
| 本文・出典・URL位置 | 現状を維持 | Aと同条件 |
| 投稿回数・間隔 | 通常運用 | 通常運用 |

- サイト導線の公開日時、固定投稿日時、冒頭比較開始日時を分けて記録する。前後に起きたニュース量・フォロワー増・検索露出なども記録し、導線の因果効果と断定しない。
- 同じ記事をA/B両方で重複投稿しない。新しい対象記事を同じジャンル内で事前に割り当てる。都合のよい結果だけ採用しない。緊急SECURITY WATCHは編集判断と正確性を優先し、初回の比較対象から外す。
- 各投稿は公開後7日（168時間）時点のviewsで揃える。途中の投稿は「未成熟」、欠損は「取得不可」。媒体側の時刻・集計粒度に制約があれば実際の観測時刻と経過時間を残し、同じ経過時間同士のみ比較する。
- 初回2週間は登録期間。その最終投稿から7日後まで待って集計する。各群4件は最低限の探索的な目安で、検定に十分な件数という意味ではない。不足時は期間を延長し、追加投稿で埋めない。
- 主指標はジャンル別・群別の7日views中央値。件数・全投稿値・範囲も併記する。母数が異なるジャンルを混ぜた平均で結論を出さない。対照中央値が0なら割合差は算出しない。
- 30%以上の差が2サイクル同方向なら採用を検討する仮基準。ただし小標本・非ランダムなニュース選択による限界を明示する。差が小さい／方向が揃わない場合は「差なし」ではなく「判断材料不足」。
- 「期間の純フォロワー増減÷同期間の投稿数」は投稿あたりの参考値。フォロー転換率や個別投稿の寄与とは呼ばない。プロフィール閲覧など分母を取得できない場合、転換率は出さない。
- MUSEのSNS集計とGA4のサイト流入は別の観測。JSTの期間、メトリクス定義、取得時刻、取得不可を記録する。

記録列：記事ID / 実投稿URL / ジャンル / A・B / 冒頭全文 / 投稿日時JST / 観測日時JST / 経過時間 / views / likes・replies等の補助値 / 欠損理由 / 同時期の変更点。
