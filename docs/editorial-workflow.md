# WORK SIGNAL 編集・承認ワークフロー

## 運用原則
- 初期投資0円・外部AI API不要。AIの分析と原稿作成はChatGPT内で行う。
- 事実・数字・日付は一次情報で照合する。確認できないものは掲載しない。
- 80点以上のみ掲載候補、90点以上は速報候補。24時間以内の重複掲載は避ける。
- 事実と考察を分け、誇張しない。著作権・配信元の利用条件を守る。
- サイト公開は人間が明示的に「承認」した後に限る。
- 2026年10月25日以降の「公開」承認には、記事公開と公式Threads・Instagramへの投稿承認を含める。ただし `social_publish: true` を明示した新しい記事だけを投稿対象にする。
- サイト公開が成功しても、SNS側の設定・審査・APIエラーによって投稿は未完了の場合がある。成功をそれぞれ別に確認する。

## 記事データ
公開記事は `data/articles.json` に格納する。配列の各要素:
- id: 重複しない英数字ID
- title: 見出し
- summary: ニュース概要（一次情報を要約した独自文）
- category: AI / 仕事 / マネジメント / お金 / 経済 / Crypto
- score: 0〜100
- published_at: YYYY-MM-DD
- source_url: HTTPSの一次情報URL
- status: published

現行サイトはこのデータから80点以上かつpublishedの項目のみ表示する。採点は編集上の選定基準であり、トップページのカードではタイトルを優先してスコアを表示しない。

### 記事形式と任意のビジュアル
- `format`: 通常記事は省略（SIGNAL BRIEF）、長文の深掘り記事は `deep_dive`（SIGNAL DEEP DIVE）。
- トップページの形式表示は小さな波形ラベルで統一し、ラベルより見出しを優先する。
- 記事のオリジナル画像があるときだけ `card_image` に `/assets/cards/<ファイル名>.webp` などを指定できる。未指定なら画像枠も表示されない。
- `card_image_alt` は画像の内容を説明する代替テキスト。装飾のみの画像なら空欄。
- 対応形式は PNG / JPEG / WebP / AVIF。画像ファイルをリポジトリの対応パスに配置してから公開する。公開ビルド時にファイルを配信先へコピーし、指定された画像が存在しなければビルドを中断する。推奨アスペクト比は16:9。
- 画像は記事の見出しの後、概要の前に配置する。画像の有無によらずタイトルが主役になる階層を維持する。

## ChatGPT内の承認
1. ChatGPTが候補を調査し、根拠・採点・Web用概要・Threads文案を提示。
2. 利用者が承認・却下・修正を指示。
3. 承認の場合のみ、GitHubの最新 `data/articles.json` を取得し、既存データを保持したまま1件追記。
4. 保存後、GitHub Actionsの公開処理が成功し、記事URLで表示できることを確認して公開処理完了を報告。
5. 新規の承認記事には `social_publish: true` を付け、Threads本文は記事URLを含めて一次情報のプレーン `https://` URLを最後に置く。Instagram用投稿文はプロフィールの公式サイトリンクに誘導する。
6. デプロイ成功後、`social-publish.yml` でMetaの公式API投稿を行う（Secretsやスイッチの設定が必要）。記事・Threads・Instagramを別々に成否報告。詳細は `docs/SOCIAL_AUTOPUBLISH.md`。

## 注意
ChatGPTのボタンはそれだけではGitHub更新を実行しない。ボタン操作で新しい会話指示を送った後、接続されたGitHubツールで保存処理を行う。
SNS公式API自動投稿のコードは実装済み。ただしアカウント認証・GitHub Secrets・有効化変数の設定が済むまで外部投稿されない。
