# WORK SIGNAL 編集・承認ワークフロー

## 運用原則
- 初期投資0円・外部AI API不要。AIの分析と原稿作成はChatGPT内で行う。
- 事実・数字・日付は一次情報で照合する。確認できないものは掲載しない。
- 80点以上のみ掲載候補、90点以上は速報候補。24時間以内の重複掲載は避ける。
- 事実と考察を分け、誇張しない。著作権・配信元の利用条件を守る。
- サイト公開は人間が明示的に「承認」した後に限る。
- Threadsは当面手動投稿。投稿文末尾に一次情報のプレーンURLを付ける。サイト公開後は自サイトURLも案内できる。
- サイト記事を公開してもThreads投稿が完了したとは扱わない。

## 記事データ
公開記事は `data/articles.json` に格納する。配列の各要素:
- id: 重複しない英数字ID
- title: 見出し
- summary: ニュース概要（一次情報を要約した独自文）
- category: AI / 仕事 / マネジメント / お金 / 経済 / Crypto
- score: 0〜100
- published_at: YYYY-MM-DD
- source_url: HTTPSの一次情報URL
- status: published

現行サイトはこのデータから80点以上かつpublishedの項目のみ表示する。

## ChatGPT内の承認
1. ChatGPTが候補を調査し、根拠・採点・Web用概要・Threads文案を提示。
2. 利用者が承認・却下・修正を指示。
3. 承認の場合のみ、GitHubの最新 `data/articles.json` を取得し、既存データを保持したまま1件追記。
4. 保存後、GitHubのコミット結果を確認して公開処理完了を報告。
5. Threads文案はユーザーに提示し、投稿はユーザーが実行。

## 注意
ChatGPTのボタンはそれだけではGitHub更新を実行しない。ボタン操作で新しい会話指示を送った後、接続されたGitHubツールで保存処理を行う。
定期収集・自動通知・Threads APIによる自動投稿は未実装。
